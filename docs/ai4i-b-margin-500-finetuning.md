# AI4I B_margin_500 파인튜닝 실험 기록

작성일: 2026-11-18  
대상 모델: `laya-ai4i-fp32-B_margin_500`  
목적: B 모델의 학습 데이터, 입력 변환, 파인튜닝 설정, 가중치 저장 방식과 평가 결과를 기록한다.

## 1. 실험 개요

B_margin_500은 사전 학습된 **Laya multilingual**을 AI4I 2020 센서 데이터로 파인튜닝한 5종 설비 상태 분류 모델이다. 기존 v7의 9개 특징에 **고장 기준선과의 거리 및 과부하 한계 7개**를 추가해 총 16개 항목을 입력한다. 학습용 데이터는 500건이며 그중 450건을 가중치 업데이트에, 50건을 확률 보정에 사용했다.

팀 노트북의 검증 80건에서 **74건(92.50%, Macro-F1 0.8727)**을 맞혀 4개 버전 중 B가 선택됐다. 시험 80건에서는 **77건(96.25%, Macro-F1 0.9399)**을 맞혔다. 같은 시험 ID·라벨·센서값과 입력 변환을 사용한 로컬 평가에서도 결과가 일치했다.

## 2. 학습 데이터와 분할

### 원본 데이터와 라벨

- 원본은 [UCI AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i%2B2020%2Bpredictive%2Bmaintenance%2Bdataset)이다. 공정 센서와 고장 사례를 모사한 합성 데이터이며, 노트북에 포함된 원본은 10,000행·14열이다.
- 팀의 `splits.csv`와 AI4I 데이터를 `UDI`로 일대일 결합했다. 분할에는 원래 학습 241건, 검증 80건, 시험 80건이 들어 있다.
- `RNF`(무작위 고장)가 있거나 여러 고장 플래그가 동시에 켜진 행은 제외했다. `Machine failure=1`이고 TWF·HDF·PWF·OSF 중 하나만 켜진 행은 해당 고장으로 분류한다. 고장 플래그가 없고 `Machine failure=0`인 행은 정상이다. 원본 플래그로 재구성한 라벨이 `splits.csv`의 라벨과 일치하는지 검사했다.
- 5개 라벨은 **정상, 열 방출 장애(HDF), 동력 고장(PWF), 과부하 고장(OSF), 공구 마모 고장(TWF)**이다.

### B 모델의 500건 구성

1. 기존 학습 분할의 **241건**을 사용했다.
2. `splits.csv`에 들어 있는 모든 UDI를 후보에서 제외한 뒤, 라벨 조건을 만족하는 남은 고장 **5건(모두 열 방출 장애)**을 추가했다. 정상 후보는 9,543건이었다.
3. 나머지는 원본 정상 사례 **254건**으로 채웠다. 이 중 약 65%를 기준선 근처 사례에 배정하는 설정(`HARD_NORMAL_SHARE=0.65`)을 사용했다. 해당 목표를 열 방출 30%, 동력 30%, 과부하 30%, 공구 마모 10%로 나누고, 할당 수는 코드에서 각각 반올림했다.
4. 열 방출·동력·과부하는 기준선에서 가까운 정상 행부터 뽑았다. 공구 마모 쪽은 마모 200~240분 구간에서 일부를 추출했다. 이때 다른 고장 기준선용 추출과 나머지 무작위 정상 추출에서는 마모 **195~245분** 구간을 제외했다. 이미 뽑힌 행은 다시 뽑지 않았으며 B의 샘플링 시드는 `0`이었다.
5. 학습 UDI가 유일하며 검증·시험 UDI와 겹치지 않는지 검사했다. Laya 로그에도 검증과 학습·보정 간 중복이 0건으로 기록됐다.

정상 사례를 고를 때 사용한 거리는 다음과 같다. 값이 작은 사례를 우선하며, 이 점수 자체는 모델에 전달하는 16개 특징에 포함하지 않는다.

| 대상 | 정상 사례 선별 점수 |
|---|---|
| 열 방출 | `max(온도차 − 8.6, 0) / 1.0 + max(rpm − 1380, 0) / 150` |
| 동력 | 두 동력 한계(3500W, 9000W)까지의 절대 거리 중 작은 값 ÷ 800 |
| 과부하 | 제품 유형별 한계와 마모×토크 사이의 절대 거리 ÷ 1500 |
| 공구 마모 | 200~240분이면 추출 후보. 이 구간에서 무작위 추출 |

| 상태 | 학습용 풀(보정 포함) | 검증 | 시험 |
|---|---:|---:|---:|
| 정상 | 314 | 20 | 20 |
| 열 방출 장애 | 66 | 20 | 20 |
| 동력 고장 | 48 | 16 | 16 |
| 과부하 고장 | 46 | 16 | 16 |
| 공구 마모 고장 | 26 | 8 | 8 |
| **합계** | **500** | **80** | **80** |

학습용 풀을 `calib_frac=0.1`로 나눠 **학습 450건·보정 50건**을 사용했다. 표의 클래스별 건수는 분리 전 500건 기준이다.

## 3. 모델 입력과 정답 형식

한 행에 `state`, `questions`, `expected`, `meta`가 들어 있는 JSONL로 저장한다. `state`는 수치와 제품 유형을 담은 **JSON 객체**다. 질문은 `diagnosis` 한 개이며, 유형은 `choice`다. 한국어 지시문과 5가지 상태 설명은 모델 폴더의 `questions.json`에 있다. 학습 시 정답은 `expected.diagnosis`에 넣는다. `meta.UDI`는 사례를 대조할 때 사용한다. 저장된 모델 평가에서는 `model.predict(row["state"], QUESTIONS)`의 `answers.diagnosis.choice`를 채점했다.

### 기본 특징 9개

| 항목 | 키 | 값 또는 계산 |
|---|---|---|
| 제품 유형 | `product_type` | L, M, H |
| 공기 온도 | `air_temperature_K` | 원본, K |
| 공정 온도 | `process_temperature_K` | 원본, K |
| 회전 속도 | `rotational_speed_rpm` | 원본, rpm |
| 토크 | `torque_Nm` | 원본, N·m |
| 공구 마모 시간 | `tool_wear_min` | 원본, 분 |
| 공정·공기 온도차 | `temperature_gap_K` | 공정 온도 − 공기 온도, 소수 둘째 자리 |
| 동력 | `power_W` | 토크 × rpm × 2π ÷ 60, 소수 둘째 자리 |
| 마모×토크 | `wear_torque` | 공구 마모 시간 × 토크, 소수 둘째 자리 |

### B 모델의 추가 특징 7개

아래 순서로 추가한다. 거리 계산에는 위에서 표시용으로 반올림하기 전의 온도차, 동력, 마모×토크를 사용한다.

| 키 | 계산 | 해석 |
|---|---|---|
| `overstrain_limit_minNm` | L=11,000, M=12,000, H=13,000 | 제품 유형별 과부하 한계, min·N·m |
| `gap_minus_8.6K` | 온도차 − 8.6, 소수 둘째 자리 | 음수이면 열 방출 조건 중 온도차 조건 충족 |
| `rpm_minus_1380` | rpm − 1380 | 음수이면 열 방출 조건 중 속도 조건 충족 |
| `power_minus_3500W` | 동력 − 3500, 소수 첫째 자리 | 음수이면 동력 부족 조건 충족 |
| `9000W_minus_power` | 9000 − 동력, 소수 첫째 자리 | 음수이면 동력 과다 조건 충족 |
| `overstrain_limit_minus_wear_torque` | 과부하 한계 − 마모×토크, 소수 첫째 자리 | 음수이면 과부하 조건 충족 |
| `tool_wear_minus_200min` | 공구 마모 시간 − 200 | 0~40이면 공구 교체·고장 생성 구간 |

열 방출 장애의 생성 조건은 온도차와 회전 속도 조건을 **둘 다** 충족하는 경우다. 공구 마모는 200~240분 구간에서도 고장과 교체가 무작위로 나뉘므로, 마모 시간만으로 모든 사례의 실제 라벨을 판정할 수 없다. [AI4I 원본 생성 규칙](https://archive.ics.uci.edu/dataset/601/ai4i%2B2020%2Bpredictive%2Bmaintenance%2Bdataset)

## 4. 파인튜닝 환경과 파라미터

노트북은 Kaggle의 **Tesla T4**에서 실행했다. GPU 확인 셀에는 `Tesla T4`, 학습 로그에는 `cuda:0`가 기록됐다. 노트북 메타데이터는 Python **3.13.16**이다. 설치 명령과 모델의 `run_config.json`은 Laya **0.4.31**을 지정한다. 파인튜닝은 `finetune(..., "multilingual", ...)`로 시작했다. 저장된 인코더는 `jhu-clsp/mmBERT-base`(ModernBERT, 22개 층, hidden size 768, attention head 12개)이고, Laya 분류 헤드는 2개 층이다.

### 노트북에서 명시한 설정

```python
cfg = TrainConfig(
    epochs=16,
    micro_batch=4,
    grad_accum=4,
    loss="rlcd",
    shuffle_options=("choice",),
    seed=0,
    eval_data="/kaggle/working/ai4i_validation_margin.jsonl",
)
# 입력: /kaggle/working/ai4i_train_B_margin_500.jsonl
# 학습 출력: /kaggle/working/ckpt_B_margin_500
```

micro batch 4에 gradient accumulation 4를 적용했다. 실효 배치는 업데이트당 최대 **16건**이고, 로그의 업데이트 예산은 **29회/epoch × 16 epoch = 464회**다. 마지막 누적 구간에는 16건보다 적을 수 있다. 로그에는 `scheduler.step()` 호출 순서에 대한 PyTorch 경고가 있다. 464회는 설정으로 계산한 예산이며, 실제 가중치 업데이트 횟수나 경고의 영향을 별도로 측정한 값은 없다.

### 저장된 학습 보고서의 전체 설정

| 항목 | 값 |
|---|---|
| 학습 횟수와 배치 | `epochs=16`, `micro_batch=4`, `grad_accum=4` |
| 인코더 / 분류 헤드 학습률 | `encoder_lr=2.5e-5`, `head_lr=1e-4` |
| 최저 학습률 | `min_lr=1e-6` |
| 가중치 감쇠와 그래디언트 제한 | `weight_decay=0.01`, `grad_clip=1.0` |
| 손실 함수 | `loss="rlcd"`, `rl_samples=4` |
| RLCD 탐색 잡음 | `sigma_start=0.4`, `sigma_end=0.1` |
| RLCD 점수 가중치 | `w_sph=0.75`, `w_rps=1.0` |
| 클래스 선택지 순서 | `shuffle_options=["choice"]` |
| 라벨 스무딩 / 인코더 동결 | `label_smoothing=0.0`, `freeze_encoder=false` |
| 무작위 시드 | `seed=0`, `calib_seed=20260922` |
| 확률 보정 데이터 | `calib_frac=0.1`, `calib_max=400` |
| 응답 보류 기준의 보정 설정 | `target_error=0.1`, `min_abstain_n=10` |
| 입력 및 헤드 길이 재정의 | `max_len=null`, `head_max_len=null` |
| 선택지 배치 재정의 | `option_layout=null` |
| 혼합 정밀도, 그래디언트 체크포인팅 | `amp=null`, `gradient_checkpointing=null` (버전 기본 동작) |
| 로그 간격 | `log_every=100` |
| CSV용 기본 옵션 | `text_column="text"`, `label_column="label"`, `question_id="label"`, `instructions=null` |
| 검증 데이터 파일 | `eval_data="/kaggle/working/ai4i_validation_margin.jsonl"` |

- 0.4.31 배포 커밋의 학습 코드는 **AdamW**와 **CosineAnnealingLR**를 사용한다. 인코더와 헤드를 별도 학습률 그룹에 넣고, 코사인 스케줄은 전체 업데이트 예산과 최저 학습률을 적용한다. AdamW의 `betas`, `eps`는 Laya 설정에서 별도로 전달하지 않았다. [Laya 0.4.31 학습 코드](https://github.com/NandhaKishorM/laya/blob/3a38cbe83f6ef556f3125fb0065fdc5a55d05792/laya/train.py#L589-L621)
- RLCD 코드는 로짓에 잡음을 더한 샘플의 보상으로 계산한 항과 soft cross-entropy를 결합한다. 탐색 잡음 `sigma`는 에폭에 따라 0.4에서 0.1로 선형 감소한다. [Laya 0.4.31 RLCD 구현](https://github.com/NandhaKishorM/laya/blob/3a38cbe83f6ef556f3125fb0065fdc5a55d05792/laya/train.py#L458-L480)
- `freeze_encoder=false`이므로 인코더와 헤드를 함께 업데이트한다. 저장된 에이전트 설정의 `max_len`은 1,024, `head_max_len`은 256, `max_prefixes`는 6이다. 표의 `null`은 해당 값을 학습 인자로 재정의하지 않았다는 뜻이다.
- 0.4.31 공개 구현은 `amp`가 미지정이면 CUDA 학습에서 FP16 autocast와 GradScaler를 켠다. 이때 미지정된 gradient checkpointing도 켜는 경로를 사용한다. 노트북의 `LAYA_CUDA_AMP="float32"`는 **저장 모델 평가 시 CUDA 추론**을 FP32로 요청한 설정이다. 최종 파일의 저장 dtype과 학습 dtype은 구분한다. [학습 시 정밀도 설정](https://github.com/NandhaKishorM/laya/blob/3a38cbe83f6ef556f3125fb0065fdc5a55d05792/laya/train.py#L576-L604) · [평가 시 정밀도 설정](https://github.com/NandhaKishorM/laya/blob/3a38cbe83f6ef556f3125fb0065fdc5a55d05792/laya/agent.py#L274-L295)

## 5. 확률 보정과 가중치 저장

- `choice` 보정 표본은 50건이다. `train_report.json`에 기록된 temperature는 **4.648645401000977**, 보정 표본 정확도는 **94%**, 평균 신뢰도는 **0.9416869225086031**이다. 보정 경고 목록은 비어 있다.
- 저장된 보류 임계값은 `choice:3-5=0.7557`이다. 검증·시험 분류표는 `answers.diagnosis.choice`를 그대로 채점한 결과다. 별도의 보류 정책을 적용한 결과는 기록하지 않았다.
- B 실행의 학습 함수 경과시간은 **534초**, 마지막 epoch 평균 loss는 **0.3913**이었다.

최상위 `model.safetensors`의 텐서 **170개**는 모두 **F32**로 저장됐다. 파일 크기는 **1,287,653,720바이트**(약 1,288MB, 1,228MiB)다. 검증한 파일의 SHA-256은 `419add916f11a3b6a144022efbe24f8d2b8014641f1635713dd77409379c2958`이다. 저장 폴더에는 `encoder/`, `tokenizer/`, `rl_agent_config.json`, `questions.json`, `run_config.json`, `train_report.json`도 함께 있다.

**FP32 파일의 실제 값은 FP16으로 그대로 표현할 수 있다.** Laya 0.4.31의 공개 저장 코드는 `save_file`로 넘기기 전에 가중치를 FP16으로 변환한다. 팀 노트북은 그 `save_file`을 감싸 전달받은 텐서를 FP32로 변환해 저장한다. 실물 파일의 **321,908,998개 값 전부**를 FP16으로 내렸다가 FP32로 되돌린 결과, 원래 저장 값과 비트 단위로 일치했다. 따라서 이 체크포인트의 **가중치 값을 유지한 채 FP16 파일로 다시 저장할 수 있다.** 실제 모델 응답 시간은 로더와 연산 정밀도를 포함한 실행 환경에서 별도로 측정한다. [Laya 0.4.31 체크포인트 저장 코드](https://github.com/NandhaKishorM/laya/blob/3a38cbe83f6ef556f3125fb0065fdc5a55d05792/laya/train.py#L538-L549)

## 6. 평가 결과와 해석

### 검증 80건

| 버전 | 입력 | 학습용 행 | 정확도 | Macro-F1 | 공구 마모 재현율 |
|---|---|---:|---:|---:|---:|
| A_v7_500 | 기존 9개 | 500 | 82.50% (66/80) | 0.7962 | 50.0% (4/8) |
| **B_margin_500** | **16개** | **500** | **92.50% (74/80)** | **0.8727** | **37.5% (3/8)** |
| C_margin_1000 | 16개 | 1,000 | 86.25% (69/80) | 0.7719 | 12.5% (1/8) |
| D_margin_2000 | 16개 | 2,000 | 90.00% (72/80) | 0.7667 | 0.0% (0/8) |

노트북은 검증 정확도가 높은 순으로 고르고, 동률이면 Macro-F1이 높은 순, 그래도 동률이면 고장을 정상으로 놓친 건수가 적은 순으로 고른다. B의 유형별 정답 건수는 정상 **19/20**, 열 방출 **20/20**, 동력 **16/16**, 과부하 **16/16**, 공구 마모 **3/8**이다. 모델 폴더의 검증 보고서에서 B의 정확도는 사전 학습 모델 **20.00%**에서 파인튜닝 후 **92.50%**로, 평가 loss는 **2.3112**에서 **0.2921**로 변했다.

### 시험 80건

팀 노트북은 검증으로 선정한 B를 시험 분할에서 한 번 채점했다.

| 유형 | 정답 건수 | 재현율 |
|---|---:|---:|
| 정상 | 20/20 | 100% |
| 열 방출 장애 | 20/20 | 100% |
| 동력 고장 | 16/16 | 100% |
| 과부하 고장 | 16/16 | 100% |
| 공구 마모 고장 | 5/8 | 62.5% |
| **전체** | **77/80** | **정확도 96.25%** |

Macro-F1은 **0.9399**, 출력 적합률은 **100%**다. 오답 3건은 모두 공구 마모 고장을 정상으로 분류한 경우다. 노트북의 Tesla T4 단건 판단 시간 중앙값은 **48.9ms**(예열 3건, CUDA 동기화 후 호출 시간 측정)였다.

로컬 PC에서 동일한 시험 사례 80건의 ID, 정답, 원본 센서값을 대조하고 분류를 재실행했다. 이 실행은 CPU와 Laya 0.4.35를 사용했다. B의 정확도 **96.25%**, Macro-F1 **0.9399**가 재현됐고, 기존 저장 v7은 **87.50%(70/80)**, **0.8224**였다. 같은 로컬 실행의 단건 모델 판단 중앙값/p95는 B **1,095/1,222ms**, v7 **183/248ms**였다. 이 값은 게이트웨이가 MQTT로 응답하는 왕복 시간이 아닌 모델 호출 시간이다.

### 결과를 인용할 때 구분할 사항

- 같은 노트북의 A→B 비교에서 검증 정확도는 **10.0%p** 높아졌다. 동력은 **11/16→16/16**, 열 방출은 **16/20→20/20**으로 늘었고 공구 마모는 **4/8→3/8**로 줄었다.
- A와 B는 학습용 행 수와 명시한 파인튜닝 설정이 같지만, A는 추가 정상 행을 무작위로 뽑고 B는 경계에 가까운 정상 행을 우선해 뽑았다. **입력 특징과 학습 행 구성의 효과가 함께 반영된 비교**다. 입력 특징의 효과만 평가하려면 학습에 들어가는 UDI를 고정한 비교가 필요하다.
- `A_v7_500`은 팀원 노트북에서 재학습한 버전이다. 기존에 공유된 `laya_ai4i_v7`과 별개의 체크포인트다. 기존 저장 모델과 B 사이에는 질문 문구, 선택지 섞기 설정과 가중치 저장 형식도 차이가 있다.
- C, D에서는 학습 크기를 늘릴 때 고장 클래스별 건수는 유지되고 정상 사례만 늘었다. 이번 학습 조건에서는 공구 마모 재현율이 낮아졌으며, 학습량 증가 일반의 효과로 단정할 수 없다.
- 시험은 합성 데이터 한 분할에서 수행했고 공구 마모는 8건이다. 현재 점수로 현장 성능이나 공구 마모 판정의 이론적 상한을 확정할 수 없다.

## 2. 실험 목적과 데이터

AI4I 2020 Predictive Maintenance Dataset의 센서 데이터를 이용해 Laya가 다음 다섯 가지 상태 중 하나를 선택하도록 파인튜닝한다.

1. 정상
2. 공구 마모 고장(TWF)
3. 열 방출 장애(HDF)
4. 동력 고장(PWF)
5. 과부하 고장(OSF)

노트북은 Kaggle에 연결된 `ai4i2020.csv`와 `splits.csv`를 불러와 UDI를 기준으로 `one_to_one` 병합한다. 저장된 출력에서 기존 분할은 **학습 241건, 검증 80건, 시험 80건**, 총 401건이며 센서값 누락은 0건이다.

팀원의 `splits.csv`는 기존 백업과 첫 다섯 UDI 및 분할 건수가 일치하지만, 노트북에 전체 파일 해시나 모든 UDI가 기록되어 있지 않아 **기존 36회 모델의 분할과 완전히 동일하다고 아직 확정할 수 없다.** 사용한 `splits.csv` 원본의 전체 UDI와 split을 비교해야 한다.

## 3. 입력과 질문 형식

학습 파일은 JSONL이고, 각 행에 `state`, `questions`, `expected`를 저장한다. `state`는 JSON 객체 자체가 아니라 센서값 딕셔너리를 `json.dumps`로 직렬화한 **JSON 형식의 문자열**이다. Laya가 센서값을 문자열로 처리하는 입력 표현이다.

v1~v3의 센서 입력은 공기 온도(K), 공정 온도(K), 회전 속도(rpm), 토크(Nm), 공구 마모(min)다. 예시 구조는 다음과 같다.

```json
{
  "state": "{\"air_temperature_K\": 300.6, \"process_temperature_K\": 310.3, \"rotational_speed_rpm\": 1648, \"torque_Nm\": 30.5, \"tool_wear_min\": 217}",
  "questions": {"diagnosis": "실제 파일에는 choice 질문과 다섯 선택지가 들어감"},
  "expected": {"diagnosis": "공구 마모 고장"}
}
```

위 예시는 구조를 보여주기 위해 `questions` 내용을 요약한 것이므로 학습용으로 그대로 실행할 수 없다. 실제 노트북은 `diagnosis` 질문에 다섯 선택지와 설명을 포함한다.

v4 이후 코드에서는 다음 항목이 추가된다.

| 입력 항목 | 구성 방식 |
|---|---|
| `product_type` | AI4I 원본의 제품 유형 |
| `temperature_gap_K` | 공정 온도 − 공기 온도 |
| `power_W` | 토크 × 회전 속도 × 2π / 60 |
| `wear_torque` | 공구 마모 × 토크 |

이 파생값들은 원본 센서값으로 계산되며, AI4I의 고장 생성 기준과 관련된 도메인 정보를 반영한다. 따라서 이를 넣은 실험은 입력 항목이 추가된 실험으로 기록한다.

## 4. 학습 데이터 500건 확장

노트북은 기존 401건의 UDI를 원본 CSV에서 제외한 나머지를 대상으로, 무작위 고장(RNF)과 중복 고장 등을 제외한 뒤 단일 고장 사례를 우선 추가하고 부족한 수를 정상 사례로 채운다. 샘플링 시드로 42를 사용한다.

저장된 500건 생성 셀의 출력은 다음과 같다.

| 상태 | 건수 |
|---|---:|
| 정상 | 314 |
| 공구 마모 고장 | 26 |
| 열 방출 장애 | 66 |
| 동력 고장 | 48 |
| 과부하 고장 | 46 |
| **합계** | **500** |

노트북은 이 500건의 UDI가 유일하고, 기존 검증·시험 UDI와 겹치지 않는다는 검사를 실행했으며 저장 출력은 각각 **중복 0건**이다. 이 확인은 UDI 기준이며 모든 종류의 데이터 누출이 없다는 보장은 아니다.

**이전 예비 평가 데이터:** 기존 실험은 별도로 확인했던 UDI 10건을 최초 분할에서 제외했다. 500건 확장 코드는 기존 401건만 제외한다. 기준 백업에 기록된 해시와 일치하는 로컬 CSV 및 기준 분할로 재계산하면 이 예비 10건 중 HDF 5건(UDI 4088, 4832, 4652, 3807, 4769)이 추가 학습 대상으로 선택된다. 팀원 노트북에서 실제로 사용한 CSV와 분할의 전체 해시는 확인되지 않았으므로, 입력이 같다면 포함되는 조건부 결과다. 해당 10건은 독립 평가로 재사용하지 않는 것이 좋다.

## 4-1. v7 파인튜닝 절차와 파라미터 상세

이 절은 노트북의 v7 데이터 생성·학습 코드(셀 33~36)에 적힌 **실행 계획**이다. 해당 셀의 출력은 저장되지 않았으므로 실제 실행 환경이나 학습 완료를 확인한 결과가 아니다.

### 학습 절차

1. Kaggle 입력에서 `splits.csv`와 `ai4i2020.csv`를 읽고 `UDI`로 병합한다. 기존 분할의 학습 241건은 기본 학습 데이터로 사용한다.
2. 기존 분할 401건의 UDI를 원본에서 제외한 다음, 라벨 조건을 만족하는 단일 고장을 먼저 추가하고 나머지를 정상 데이터로 채워 학습용 500건을 구성한다. 추가 사례 샘플링에는 `random_state=42`를 사용한다.
3. 공기·공정 온도, 회전 속도, 토크, 공구 마모, 제품 유형과 온도 차이·계산 동력·마모×토크를 `json.dumps()`로 직렬화하여 `state`에 넣는다. 각 사례에 동일한 다섯 선택지의 `diagnosis` 질문과 정답을 붙인다.
4. 500건을 `train_features.jsonl`, 기존 검증 80건을 `validation_features.jsonl`로 저장한다. 같은 입력 형식으로 시험 80건도 생성한다. 코드에는 학습용 UDI의 유일성과 검증·시험 UDI와의 교집합을 검사하는 `assert`가 있다.
5. `laya-train`에서 **원본 `multilingual` 체크포인트**를 시작점으로 삼아 16 epochs 동안 파인튜닝하도록 설정한다. v6 또는 기존 36회 모델의 이어 학습은 아니다.
6. 저장한 v7 모델을 불러와 검증셋에 예측을 수행하고 정확도, 클래스별 분류 보고서와 혼동표를 출력하도록 작성되어 있다. 마지막 셀은 v7 모델 폴더를 ZIP으로 압축한다.

### v7 학습 명령

```bash
laya-train \
  --data /kaggle/working/train_features.jsonl \
  --base multilingual \
  --out /kaggle/working/laya_ai4i_v7 \
  --eval-data /kaggle/working/validation_features.jsonl \
  --epochs 16 \
  --micro-batch 4 \
  --grad-accum 4 \
  --loss rlcd \
  --seed 0
```

### 코드에 명시된 설정

| 항목 | v7 코드 값 | 의미 |
|---|---|---|
| 초기 모델 | `multilingual` | Laya의 다국어 기본 모델에서 시작. 정확한 모델 revision은 미확인 |
| 학습 데이터 | `train_features.jsonl`, 구성 목표 500건 | 센서값과 파생값을 담은 JSON 형식 문자열 |
| 검증 데이터 | `validation_features.jsonl`, 기존 분할 80건 | 학습 후 평가용. 최종 독립 시험 결과는 아님 |
| 판단 작업 | `diagnosis` choice, 5개 선택지 | 정상·열 방출·동력·과부하·공구 마모 고장 분류 |
| epochs | `16` | 학습용 데이터를 반복하는 설정 횟수 |
| micro batch | `4` | 한 번의 작은 배치 크기 |
| gradient accumulation | `4` | 기울기를 4개 배치에 걸쳐 누적. 완전한 누적 구간의 유효 배치는 최대 16건이며 마지막 구간은 작을 수 있음 |
| 손실 함수 | `rlcd` | Laya에서 제공하는 학습 목적 함수 |
| 학습 시드 | `0` | v7 `--seed` 값. 500건 추가 샘플의 `random_state=42`와 별개 |
| 모델 출력 경로 | `/kaggle/working/laya_ai4i_v7` | 학습 결과를 저장하도록 지정한 경로 |
| 실행 프로그램 | `laya-train` | 설치된 Laya 패키지의 CLI로 실행하도록 작성 |

### 코드에서 명시하지 않은 설정

v7 명령에는 **encoder·head 학습률, 옵티마이저, 가중치 감소, 학습률 스케줄러, AMP·gradient checkpointing, calibration 비율과 시드, 체크포인트 revision**이 명시되어 있지 않다. 실행 시 설치된 Laya 버전과 환경의 기본값이 적용될 수 있으나, **공유된 노트북에는 v7의 실제 설정 파일이나 학습 출력이 없어 정확한 값을 확정할 수 없다.** 실행 시점의 `training_config.json`, `train_report.json` 또는 노트북 로그로 확인한다.

설치 셀의 저장 출력에는 `laya==0.4.35`가 보이지만 명령이 `pip install -U laya`이므로 v7 실행 시에도 같은 버전이었는지 확인해야 한다. GPU 이름과 PyTorch·CUDA 버전 역시 v7 실행 로그 또는 환경 기록으로 별도 확인한다.

v3 로그의 **450건 학습·50건 보정**은 v3 실행에서 확인된 값이다. v7도 500건을 전달하도록 작성되어 있지만 실행 결과가 저장되지 않았으므로, 이를 v7의 확정 보정 건수로 기재하지 않는다.

## 5. 모델별 설정과 저장된 결과

노트북의 설치 로그에는 Laya **0.4.35**, PyTorch **2.11.0+cu130**, Transformers **5.20.2**가 보인다. 설치 명령은 `pip install -U laya`여서 나중에 실행하면 버전이 달라질 수 있다. 기본 모델은 `--base multilingual`이며, 사용한 체크포인트의 정확한 revision은 이 노트북 출력에서 확인되지 않는다.

| 버전 | 학습용 데이터·입력 | 주요 설정 | 이 노트북에 저장된 결과 |
|---|---|---|---|
| v1 | 241건, 기본 5개 센서 | 4 epochs. 로그상 micro batch 8, gradient accumulation 8 | 학습 217·보정 24, 검증 80건에서 **정확도 30.00%** |
| v2 | 241건, 기본 5개 센서 | 12 epochs, micro batch 4, gradient accumulation 4 | 학습 217·보정 24, 검증 80건에서 **정확도 38.75%** |
| v3 | 500건, 기본 5개 센서 | 12 epochs, micro batch 4, gradient accumulation 4 | 로그상 학습 450·보정 50. **7/12 epoch까지 출력**, 최종 결과 확인 불가 |

v1은 내부 보정 항목이 24건에 불과하다는 경고와 클래스 편향으로 출력이 붕괴했을 가능성을 나타내는 경고를 기록했다. v1~v3 로그에는 학습률 스케줄러 호출 순서 경고도 나타난다. **이 경고가 결과에 미친 원인과 크기는 확인되지 않았다.** 데이터가 생성되기 전에 실행된 초기 `laya-evals validate` 셀에도 파일을 찾지 못했다는 출력이 있다.

v4를 시험셋으로 평가하는 코드와 v7 모델 폴더를 ZIP으로 압축하는 코드는 존재하지만, 공유 노트북에는 실행 출력이 없다. 코드 존재만으로 시험 또는 백업 완료를 판단하지 않는다.

## 6. 기존 36회 모델과 비교

기존 36회 AI4I 모델은 백업에 기록된 검증 80건 중 69건을 맞혀 **86.25%, Macro-F1 0.841184**였다. 별도 공유된 v7 화면은 검증 80건 중 70건을 맞혀 **87.5%**라고 보고한다. 검증 사례가 정확히 동일하다면 1건 차이지만, 현재 팀원 노트북에 사용된 분할 전체가 같은지는 미확인이다.

두 모델은 학습 사례 수뿐 아니라 다음 조건도 다르다.

| 조건 | 기존 36회 모델 | 팀원 v7 코드 |
|---|---|---|
| 학습용 입력 | 241건 | 500건 |
| 입력 표현 | 한국어 항목명 문자열 | 영문 키의 JSON 형식 문자열 |
| 파생 입력 | 온도 차이 포함, 계산 동력 제외 | 온도 차이, 계산 동력, 마모×토크 포함 |
| 학습 횟수·시드 | 36 epochs, seed 42 | 16 epochs, seed 0 |
| 배치 설정 | micro batch 2 × accumulation 8 | micro batch 4 × accumulation 4 |
| Laya | 0.4.21 | 설치 출력 0.4.35. v7 실행 환경은 추가 확인 필요 |

따라서 보고된 정확도 차이를 **학습 데이터 증가나 JSON 입력의 효과 하나로 해석할 수 없다.** 상태별 재현율과 Macro-F1도 함께 비교해야 한다.

## 7. 한계와 다음 확인 사항

1. 팀원에게 **v7 실행 완료 출력이 저장된 최신 노트북**, 모델 백업 ZIP, 실제 사용한 `splits.csv`를 받는다.
2. `train500`의 추가 UDI 목록과 검증 80건의 정답·예측·혼동행렬·Macro-F1, 학습 로그와 보정 건수, 모델과 패키지 버전·revision을 확보한다. 노트북의 v7 ZIP 생성 코드는 모델 폴더만 압축하므로 이런 기록이 모두 포함된다고 가정하지 않는다.
3. 기존 모델과 같은 검증 UDI를 사용했는지 확인한다. 검증셋을 반복해 모델을 선택한 이력이 있으므로, 최종 성능은 학습·모델 선택에 사용하지 않은 독립 데이터로 확인한다. 기존 시험셋은 과거 확인 이력 여부를 먼저 점검한다.
4. AI4I 모델은 설비 고장 분류 예비 실험이다. 프로젝트의 MQTT 컨베이어 상태·대응 JSON과는 입력 및 정답이 다르므로 해당 시나리오는 별도로 학습·평가한다.
5. INT8 양자화 또는 지식 증류의 완료와 성능은 이 노트북에서 확인되지 않았다. 이후 같은 입력과 장치에서 별도로 측정한다.

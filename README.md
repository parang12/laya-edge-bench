## 프로젝트 소개

가상 스마트 팩토리의 생산 셀 하나를 IoT 게이트웨이로 감시합니다. 설비가 보낸 센서 기록을 바탕으로 **현재 상태**와 **필요한 운전 조치**를 판단하고, 모델을 경량화했을 때 판단 성능과 자원 사용량이 어떻게 달라지는지 확인합니다.

같은 기준 모델에서 출발한 **파인튜닝 FP32**, **INT8 양자화**, **소형 학생 FP32**에 동일한 시험 기록을 재생합니다. 전체 점수와 함께 고장을 정상으로 놓치거나, 중단 요청이 필요한 상황에서 다른 조치를 고르는 경우도 확인합니다.

## 시스템 구성

~~~mermaid
flowchart LR
    S["가상 생산 셀"] -->|"센서 메시지 발행"| B["MQTT 브로커"]
    B -->|"구독"| G["IoT 게이트웨이"]
    G -->|"최근 관측값 요약"| M["Laya 추론"]
    M -->|"진단 · 운영 조치"| R["판단 로그 · 경고 · 결과표"]
~~~

가상 설비는 정상 운전, 온도 상승, 센서 메시지 끊김과 복구를 재현합니다. 게이트웨이는 최근 온도, 온도 변화, 마지막 메시지 이후 경과 시간 등 관측값을 정리합니다. 새 메시지가 없어도 마지막 수신 시각을 기준으로 통신 상태를 점검합니다. 모델이 내린 중단 요청과 경고는 시연과 평가에 쓸 수 있도록 로그에 남깁니다.

| 판단 작업 | 모델에 묻는 질문 | 선택지 |
|---|---|---|
| **상황 진단** | 지금 설비에서 어떤 상태가 관측되는가? | 정상 · 열 이상 · 통신 장애 |
| **운영 정책 판단** | 관측된 상태에서 어떤 조치가 필요한가? | 운전 유지 · 운전 제한 · 운전 중단 요청 |

구체적인 설비 종류, 센서 단위, 관측 구간, 운영 조치의 정답 기준은 팀에서 확정합니다. 온도가 얼마나 올랐는지, 메시지가 얼마나 오래 끊겼는지에 따라 기대 조치가 달라질 수 있으므로 시나리오별 판단 근거를 기록합니다.

## 비교 실험

| 모델 | 준비 방법 |
|---|---|
| **기준 FP32** | 원본 Laya multilingual을 두 판단 작업에 맞춰 파인튜닝하고 검증셋에서 고른 체크포인트를 저장합니다. |
| **INT8 양자화** | 같은 기준 FP32 체크포인트를 양자화합니다. |
| **소형 학생 FP32** | 기준 FP32를 교사로 사용해 더 작은 학생 모델에 판단을 증류합니다. |

**평가 방법.** 학습·검증·시험 시나리오를 실행 단위로 나누고, 같은 기록에서 만든 변형은 같은 분할에 둡니다. 기준 모델과 설정을 고정한 뒤 세 모델을 같은 기기에서 실행합니다. 동일한 시험 입력과 정답표를 사용하고, 모델별 실행 환경과 측정 조건을 기록합니다.

| 측정 항목 | 비교 내용 |
|---|---|
| **판단 성능** | 진단·정책별 정확도, Macro-F1, 출력 적합률, 유형별 오판 |
| **자원 사용량** | 모델 파일 용량, 실행 중 최대 메모리, 모델 호출 지연 |
| **시나리오 기록** | 기대 진단·조치, 실제 진단·조치, 정오 및 출력 오류 |

출력 적합률은 모델이 정해진 선택지로 답한 비율입니다. 모델 호출 지연과 MQTT 전달을 포함한 전체 응답 시간은 구분해 기록합니다.

**예비 실험.** AI4I로 설비 고장 분류를 실험했고, CONTEXT에서는 프레스 동작과 RFID를 대조해 셔틀 이탈 한 건을 살펴봤습니다. 팀 시나리오에서는 정상·열 이상·통신 장애와 운영 조치를 별도로 채점할 예정입니다.

## 진행 계획

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| **1주차 · 기준 모델과 시뮬레이터** | 1명은 MQTT와 IoT 시스템을 구현하고, 2명은 진단·정책 사례를 준비해 FP32 모델을 파인튜닝합니다. | 정상·열 이상·통신 장애를 재생하고, 모델의 두 답이 결과표에 남습니다. |
| **2주차 · 경량화와 측정** | 기준 체크포인트와 공통 시험셋을 고정하고, INT8과 소형 학생 모델을 준비합니다. | 세 모델의 판단 성능과 자원 사용량을 같은 조건에서 측정합니다. |
| **3주차 · 결과 분석과 시연** | 주요 실험을 재실행하고 오판을 분석한 뒤 보고서와 발표 자료를 작성합니다. | 비교표·그래프, 논문 초안, 발표 자료, 시연 영상을 준비합니다. |

**현재 상태 · 설계 및 예비 실험 단계.** 세 모델의 비교 점수와 실행 안내는 시뮬레이터와 평가 흐름이 연결된 뒤 추가합니다.

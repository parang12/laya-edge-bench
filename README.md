## 프로젝트 소개

IoT 게이트웨이에서 센서 메시지와 수신 기록을 바탕으로 **현재 상태**와 **필요한 대응**을 판단합니다. 기준 모델과 경량화한 모델이 같은 환경에서 실행되는지 확인하고, 판단 성능과 자원 사용량을 비교합니다.

같은 기준 모델에서 출발한 **파인튜닝 FP32**, **INT8 양자화**, **소형 학생 FP32**에 동일한 시험 기록을 재생합니다. 전체 점수와 함께 센서 이상이나 수신 중단을 놓치거나, 경고가 필요한 상황에서 관측을 계속하기로 판단한 경우도 확인합니다.

## 디렉터리 구조

```text
laya-edge-bench/
├── docs/             # 시나리오와 실험 기준 문서
├── notebooks/        # 파인튜닝·경량화 실험 노트북
├── data/             # 데이터 설명과 예시
├── results/          # 실험 결과와 비교 기록
├── model_bench/      # AI4I 모델 검증·MQTT 측정·엑셀 내보내기
└── 모델_측정_실행.cmd # Windows 측정 도구 실행
```

## AI4I 모델 측정 도구

Windows와 Python이 필요합니다. Python 3.12에서 실행을 확인했습니다. 저장소를 내려받고, 처음 한 번 프로젝트 폴더에서 라이브러리를 설치합니다.

~~~powershell
python -m venv model_bench/.venv
.\model_bench\.venv\Scripts\python.exe -m pip install -r model_bench/requirements.txt
~~~

1. AI4I용 Laya 모델을 압축 해제합니다. 선택할 폴더의 최상위에 `model.safetensors`, `rl_agent_config.json`, `questions.json`, `encoder/`, `tokenizer/`가 있어야 합니다. B_margin_500이라면 `run_config.json`도 포함합니다.
2. [모델_측정_실행.cmd](./모델_측정_실행.cmd)를 열고 **모델 폴더 선택**을 누릅니다. B_margin_500에는 학습 때 사용한 16개 특징을, v7에는 기존 9개 특징을 적용합니다.
3. **모델 검증 · 80건**이나 **MQTT 테스트 · 100회**를 실행한 뒤 **엑셀로 내보내기**를 눌러 결과를 저장합니다.

| 버튼 | 기록하는 결과 |
|---|---|
| **모델 검증 · 80건** | 고정 시험 데이터의 정확도, Macro-F1, 유형별 재현율 |
| **MQTT 테스트 · 100회** | 고유 시험 80건과 반복 20건의 송수신 결과, 고유 80건의 정확도, 전체 응답 시간 중앙값·p95 |
| **엑셀로 내보내기** | 건별 정답·예측, 모델 입력·출력 시각, 판단 시간, MQTT 전체 응답 시간 |

프로그램이 PC 내부에서 MQTT 브로커를 열고 센서 요청과 모델 응답을 전달합니다. 이 측정은 프로그램을 실행한 PC의 결과입니다. 라이브러리와 모델 폴더를 준비하면 해당 측정은 인터넷 연결 없이 실행할 수 있습니다.

시험 데이터는 Stefan Matzka의 [AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i%2B2020%2Bpredictive%2Bmaintenance%2Bdataset) ([CC BY 4.0](https://creativecommons.org/licenses/by/4.0/))에서 팀 분할에 따라 80건을 골라, 측정 도구의 입력 형식으로 변환한 것입니다.

- [B_margin_500 파인튜닝 기록](./docs/ai4i-b-margin-500-finetuning.md) · 기준 모델의 입력, 학습 설정, 시험 결과
- [v7 파인튜닝 기록](./docs/ai4i-v7-finetuning.md) · 비교 모델의 학습과 평가 이력

## 시스템 구성

~~~mermaid
flowchart LR
    S["가상 IoT 센서 노드"] -->|"센서 메시지 발행"| B["MQTT 브로커"]
    B -->|"센서 메시지 전달"| G
    subgraph EDGE["IoT 게이트웨이"]
        G["게이트웨이 처리부"] -->|"최근 관측 요약"| M["Laya 경량화 모델"]
        M -->|"상태 판단 · 대응 판단"| G
    end
    G --> R["판단 로그 · 경고 · 결과표"]
~~~

가상 센서 노드는 정상 범위의 값, 범위를 벗어난 값, 메시지 끊김과 복구를 재현합니다. 첫 구현에서는 온도 센서를 예시로 사용합니다. 게이트웨이는 최근 센서값, 변화량, 마지막 메시지 이후 경과 시간을 정리해 Laya를 로컬에서 실행합니다. 메시지가 없는 동안에도 수신 상태를 확인하고 모델의 상태 판단과 대응을 로그에 남깁니다.

| 판단 작업 | 모델에 묻는 질문 | 선택지 |
|---|---|---|
| **상태 판단** | 최근 센서값과 수신 기록에서 어떤 상태가 관측되는가? | 정상 · 센서값 이상 · 데이터 수신 중단 |
| **대응 판단** | 관측된 상태에서 게이트웨이가 어떤 대응을 해야 하는가? | 계속 관측 · 경고 발생 · 연결 점검 요청 |

센서 종류와 단위, 관측 구간, 정상 범위와 수신 중단 기준은 팀에서 합의합니다. 시나리오별로 기대 상태와 기대 대응을 미리 기록합니다. 수신 중단은 게이트웨이가 관측한 상태로 채점하며, 원인을 구분하는 실험에는 추가 신호를 사용합니다.

구조도의 **Laya 경량화 모델** 자리에 기준 FP32, INT8, 소형 학생 FP32를 각각 연결해 비교합니다.

## 모델 다운로드

기준 Laya, INT8 양자화 모델, 지식 증류 학생 모델은 준비되는 대로 [GitHub Releases](https://github.com/parang12/laya-edge-bench/releases)에 게시할 예정입니다. 각 릴리스에서 모델 파일과 해당 버전의 사용 안내를 확인할 수 있습니다.

## 비교 실험

두 기법의 선택 이유와 공통 평가 조건은 [경량화 기법 선정 근거](./docs/compression-design.md)에 정리했습니다.

| 모델 | 준비 방법 |
|---|---|
| **기준 FP32** | AI4I 5개 상태를 분류하도록 파인튜닝한 B_margin_500 체크포인트를 기준으로 삼습니다. |
| **INT8 양자화** | 같은 기준 FP32 체크포인트를 양자화합니다. |
| **소형 학생 FP32** | 기준 FP32를 교사로 사용해 더 작은 학생 모델에 판단을 증류합니다. |

**평가 방법.** 학습·검증·시험 시나리오를 실행 단위로 나누고, 같은 기록에서 만든 변형은 같은 분할에 둡니다. 기준 모델과 설정을 고정한 뒤 세 모델을 같은 기기에서 실행합니다. 동일한 시험 입력과 정답표를 사용하고, 모델별 실행 환경과 측정 조건을 기록합니다.

| 측정 항목 | 비교 내용 |
|---|---|
| **판단 성능** | 상태·대응별 정확도, Macro-F1, 출력 적합률, 유형별 오판 |
| **자원 사용량** | 모델 파일 용량, 실행 중 최대 메모리, 모델 호출 지연 |
| **시나리오 기록** | 기대 상태·대응, 실제 상태·대응, 정오 및 출력 오류 |

출력 적합률은 모델이 정해진 선택지로 답한 비율입니다. 모델 호출 지연과 MQTT 전달을 포함한 전체 응답 시간은 구분해 기록합니다.

**평가 데이터.** 현재 AI4I 비교에서는 팀의 시험 분할에서 선택한 80건을 고정해 모든 모델에 같은 입력을 적용합니다. 센서 수신 중단이나 작업 대응처럼 AI4I에 없는 시나리오는 별도 실험에서 평가합니다.

## 진행 계획

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| **1주차 · 기준 모델과 시뮬레이터** | 1명은 MQTT와 IoT 시스템을 구현하고, 2명은 상태·대응 사례를 준비해 FP32 모델을 파인튜닝합니다. | 정상·센서값 이상·수신 중단을 재생하고, 모델의 두 답이 결과표에 남습니다. |
| **2주차 · 경량화와 측정** | 기준 체크포인트와 공통 시험셋을 고정하고, INT8과 소형 학생 모델을 준비합니다. | 세 모델의 판단 성능과 자원 사용량을 같은 조건에서 측정합니다. |
| **3주차 · 결과 분석과 시연** | 주요 실험을 재실행하고 오판을 분석한 뒤 보고서와 발표 자료를 작성합니다. | 비교표·그래프, 논문 초안, 발표 자료, 시연 영상을 준비합니다. |

**현재 상태 · B_margin_500과 로컬 MQTT 측정 도구를 연결했습니다.** 경량화 전후 결과를 같은 시험 분할에서 비교합니다.
